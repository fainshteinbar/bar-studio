# bfain.studio · מסמכים

אפליקציה להנפקת חשבון לתשלום (Invoice), קבלה (Payment Receipt), הודעת זיכוי (Credit Note) והצעת מחיר (Quote), כספק שירות שיושב מחוץ לישראל. ממלאים פרטים בדפדפן, במחשב או בטלפון, ומקבלים PDF וקטורי מוכן לשליחה.

- **כתובת:** https://fainshteinbar.github.io/bar-studio/invoices/
- **נתונים:** רק ב-Supabase, בפרויקט `bfain-docs`. הריפו ציבורי, ושום נתון של לקוח, מסמך או סוד לא נכנס אליו.
- **החלטות ותוכנית:** [PLAN.md](PLAN.md).

## שימוש יומיומי

**הסדר:** לקוח, אחר כך פרויקט (לא חובה), ואז מסמך.

1. **לקוח:** לקוחות → לקוח חדש. רק שם תצוגה הוא חובה. אם ממלאים שם משפטי, הוא השם שמופיע על המסמך.
2. **פרויקט:** פרויקטים → פרויקט חדש. לקוח, תיאור, סכום כולל, מטבע ותנאי תשלום. תנאי תשלום כמו `50/50` נותנים לקבלות את התוויות "מקדמה 1 מתוך 2" ו"תשלום 2 מתוך 2".
3. **חשבון או הצעת מחיר:** מהפרויקט ("חשבון מהפרויקט") או מ"מסמך חדש". מהפרויקט, השורה הראשונה מתמלאת מהתיאור והסכום שלו.
4. **טיוטה:** עורכים שורות בעברית ובאנגלית, תאריכים והערות. התצוגה המקדימה משמאל (במחשב) או בכפתור "תצוגה מקדימה" (בטלפון) מראה בדיוק את ה-PDF. טיוטה אפשר לשמור, לערוך ולמחוק. אין לה מספר, והיא מסומנת DRAFT.
5. **הנפקה:** "הנפקה" פותח חלון עם המספר שהמסמך יקבל, התאריך והסכום. אחרי האישור המסמך ננעל לתמיד. הכפתור ננעל מהלחיצה הראשונה עד שהשרת עונה, כך שלחיצה כפולה לא מנפיקה פעמיים.
6. **PDF:** "הורדת PDF" פותח את המסמך וחלון הדפסה. בוחרים "שמירה כ-PDF". במחשב: Destination → Save as PDF. ב-iPhone: שיתוף → שמירה בקבצים. שם הקובץ הוא מספר המסמך.
7. **קבלה:** בדף של חשבון שהונפק, "קבלה על תשלום". הסכום מוצע לפי תנאי התשלום, ותאריך קבלת התשלום יכול להיות לפני תאריך החשבון (מקדמה). נוצרת טיוטת קבלה, ומנפיקים אותה.
8. **תיקון:** מסמך שהונפק לא נערך ולא נמחק. "הודעת זיכוי" בדף החשבון יוצר טיוטה עם השורות שלו. משאירים רק את מה שמזכים ומנפיקים. אם זיכית את כל החשבון, הוא מסומן "בוטל".
9. **הצעת מחיר שאושרה:** "המרה לחשבון" יוצר טיוטת חשבון עם אותן שורות. אחרי שהחשבון מונפק, ההצעה מסומנת "אושרה".
10. **שכפול:** כל מסמך אפשר לשכפל לטיוטה חדשה, למשל לחשבון חודשי שחוזר על עצמו.

**מספור:** לכל סוג מסמך מספור משלו, לפי שנת תאריך ההנפקה: `INV-2026-0001`, `REC-2026-0001`, `CRN-2026-0001`, `QUO-2026-0001`. בלי חורים ובלי כפילויות. המספרים והתאריכים עולים יחד, ולכן אי אפשר להנפיק מסמך בתאריך מוקדם מהמסמך האחרון מאותו סוג. קבלה או זיכוי גם לא יכולים להיות מתוארכים לפני החשבון שלהם. אם זה קורה, חלון ההנפקה מסביר ומציע את התאריך הראשון שמותר.

**סטטוס של חשבון** מחושב אוטומטית מהקבלות והזיכויים שהונפקו: פתוח, שולם חלקית, שולם, בוטל.

**הגדרות:** כל הטקסטים שעל המסמך נערכים במסך ההגדרות, בלי לגעת בקוד. פרטי הספק, הצהרת הספק הזר בתחתית, תנאי תשלום, תנאי הצעה, הערה קבועה, מספר מזהה (כבוי כברירת מחדל ולא מוצג כשהוא ריק), מטבע וימים לתשלום. שינוי חל על מסמכים שיונפקו מעכשיו. מסמך שכבר הונפק שומר את מה שהיה בו ברגע ההנפקה.

**דשבורד:** מה התקבל החודש והשנה, מה פתוח לגבייה לפי לקוח, גרף לפי חודש, המסמכים האחרונים, ותזכורת גיבוי.

## כניסה

הכניסה היא בלינק שנשלח למייל (magic link), רק לכתובת fainshteinbar@gmail.com.

1. במסך הכניסה לוחצים "שליחת לינק כניסה".
2. מגיע מייל מ-Supabase עם לינק. **פותחים אותו באותו דפדפן ובאותו מכשיר שבו ביקשת אותו.** הלינק מאובטח בשיטת PKCE: חלק מהמפתח נשמר בדפדפן שביקש את הלינק, ולכן דפדפן אחר לא יכול להשלים את הכניסה.
3. אחרי הכניסה הדפדפן זוכר אותך, ולינק חדש נדרש רק אם יצאת (הגדרות → יציאה מהחשבון) או ניקית את נתוני הדפדפן.

בטלפון: אם אפליקציית Gmail פותחת לינקים בדפדפן משלה, מבקשים את הלינק מאותו דפדפן, או מעתיקים את הלינק מהמייל ומדביקים אותו בדפדפן שבו ביקשת.

### בעתיד: מעבר לקוד בן 6 ספרות עם Gmail SMTP

ב-Supabase החינמי אפשר לערוך את תבנית המייל רק עם שרת שליחה (SMTP) משלך. Gmail מספיק לזה:

1. **סיסמת אפליקציה ב-Google:** ב-myaccount.google.com מפעילים אימות דו-שלבי, ואז יוצרים App Password (16 תווים). זו סיסמה סודית: מדביקים אותה רק ב-Supabase, לא בצ'אט ולא בריפו.
2. **Supabase:** Authentication → Emails → SMTP Settings → Enable custom SMTP.
   - Host: `smtp.gmail.com`, Port: `465`
   - Username: `fainshteinbar@gmail.com`, Password: סיסמת האפליקציה
   - Sender email: `fainshteinbar@gmail.com`, Sender name: `bfain.studio`
3. **התבנית:** Authentication → Emails → Magic Link. בגוף ההודעה מחליפים את `{{ .ConfirmationURL }}` ב-`{{ .Token }}`, שהוא הקוד בן 6 הספרות.
4. **האפליקציה:** שינוי קטן ב-`js/auth.js` וב-`js/app.js`. במקום להמתין ללינק, מסך הכניסה מציג שדה לקוד, ובודק אותו עם `verifyOtp({ email, token, type: 'email' })`.

היתרון של קוד: אפשר לבקש בטלפון ולהקליד במחשב, או להפך. עם לינק חייבים את אותו דפדפן.

## הקמת Supabase מאפס

כך הוקם `bfain-docs` ב-19.10.2026. הצעדים כאן למקרה שצריך להקים מחדש, למשל לחשבון אחר.

1. **פרויקט:** ב-supabase.com, עם fainshteinbar@gmail.com, יוצרים פרויקט חינמי באזור Singapore. את סיסמת מסד הנתונים שומרים במנהל סיסמאות. האפליקציה לא צריכה אותה.
2. **הגדרות כניסה:** Authentication → Sign In / Providers → Email.
   - Email: מופעל. "Confirm email": מופעל.
   - "Allow new users to sign up": **כבוי**.
   - "Allow anonymous sign-ins": **כבוי**.
   - "Secure email change": מופעל.
3. **המשתמש היחיד:** Authentication → Users → Add user → Create new user. האימייל, סיסמה אקראית כלשהי (לא בשימוש), ו-Auto Confirm.
4. **כתובות:** Authentication → URL Configuration.
   - Site URL: `https://fainshteinbar.github.io/bar-studio/invoices/`
   - Redirect URLs: אותה כתובת, וגם `http://localhost:4173/invoices/` לעבודה מקומית.
5. **מסד הנתונים:** SQL Editor → New query → מדביקים את כל [supabase/install.sql](supabase/install.sql) → Run. אחר כך את [supabase/seed/settings.sql](supabase/seed/settings.sql) → Run. הקובץ `install.sql` בטוח להרצה חוזרת ולא מוחק כלום.
6. **מפתחות לאפליקציה:** Project Settings → API Keys. מעתיקים את Project URL ואת ה-**Publishable key** (לא את ה-Secret key). בטרמינל, מתיקיית הריפו:

   ```bash
   node scripts/invoices-config.mjs
   ```

   הסקריפט שואל את שני הערכים, כותב את `invoices/config.js`, ומסרב למפתח סודי.
7. **הגדרות ראשונות:** נכנסים לאפליקציה → הגדרות → כתובת בתאילנד ובדיקת הטקסטים המשפטיים. הכתובת נשמרת רק ב-Supabase.

אין פרויקט בדיקות, ובכוונה. בייצור לא מנפיקים מסמכים לבדיקה, כי מספר שהונפק נשאר לתמיד. בודקים מקומית (ראה [עבודה מקומית ובדיקות](#עבודה-מקומית-ובדיקות)).

## פריסה ועדכונים

האתר מתפרסם ב-GitHub Pages מהענף `main`, משורש הריפו. התיקייה `invoices/` מתפרסמת כמו שהיא, בלי build.

- **פרסום:** commit ו-push ל-`main`. תוך דקה-שתיים הגרסה החדשה באוויר. הסינכרון השעתי של האינסטגרם לא נוגע ב-`invoices/`.
- **לפני push:** מריצים את כל הבדיקות (למטה), ומוודאים שאין בשינוי שם של לקוח, סכום, תיאור פרויקט אמיתי, כתובת אישית או מפתח סודי.
- **שינוי במסד הנתונים:** קובץ migration חדש ב-`supabase/migrations/` (מספר הבא, למשל `0007_...sql`, שאפשר להריץ שוב בלי נזק), ואז:

  ```bash
  npm run build:install-sql
  ```

  ו-`npm run test:invoices`. בייצור מריצים ב-SQL Editor רק את קובץ ה-migration החדש. ב-`install.sql` אסור DROP; הסקריפט עוצר אם יש.

- **ספריית Supabase:** `vendor/supabase.js` היא גרסה נעולה (2.117.2), כך שהאפליקציה לא תלויה ב-CDN. עדכון רק בכוונה, עם הרצת הבדיקות.

## גיבוי

ב-Supabase החינמי אין גיבוי אוטומטי. הגיבוי הוא קובץ שנשמר אצלך.

- **איך:** הגדרות → ייצוא וגיבוי → "גיבוי JSON מלא", או "גיבוי עכשיו" בבאנר שבדשבורד. יורד קובץ `bfain-docs-backup-YYYY-MM-DD.json`. שומרים אותו בדרייב.
- **מה בתוכו:** כל הטבלאות. הגדרות, לקוחות, פרויקטים, מסמכים (כולל מה שהוקפא בכל מסמך ברגע ההנפקה), שורות ויומן הפעולות.
- **מתי:** הדשבורד מציג תזכורת אם עברו 30 יום מהגיבוי האחרון, או אם הונפק מסמך מאז. כלל אצבע: אחרי כל הנפקה.
- **CSV לרואת החשבון:** ייצוא וגיבוי → בוחרים שנה → "הורדת CSV". כל המסמכים שהונפקו בשנה: מספר, סוג, תאריך, לקוח, סכום, מטבע, סטטוס, ובנוסף תאריך קבלת התשלום ומספר החשבון של כל קבלה. נפתח ב-Excel בעברית.

**שחזור:** הקובץ מכיל את כל המידע, אבל עדיין אין כלי שטוען אותו חזרה לפרויקט חדש. ההגנה שמונעת יצירה של מסמך "מונפק" ישירות חלה גם על שחזור, ולכן צריך מסלול שחזור ייעודי (סקריפט שהופך את הגיבוי לקובץ SQL, עם אישור מפורש לשחזור). עד שהוא ייבנה, הגיבוי שומר את הנתונים ומאפשר לשחזר אותם ידנית.

## השהיה של Supabase ו-workflow שבועי

- **השהיה:** פרויקט חינמי מושהה אחרי שבוע בלי שימוש. ה-workflow `.github/workflows/invoices-keepalive.yml` פונה לפרויקט כל יום שני בבוקר עם המפתח הציבורי, כדי שזה לא יקרה.
- **אם בכל זאת הושהה:** האפליקציה לא תצליח להתחבר. נכנסים ל-supabase.com → הפרויקט → Restore project. לוקח דקה-שתיים, והנתונים נשמרים.
- **GitHub משבית workflows מתוזמנים אחרי 60 יום בלי commit בריפו.** הסינכרון השעתי של האינסטגרם מעדכן את הריפו כל הזמן, כך שזה לא אמור לקרות. אם זה קרה (תקבל על זה מייל מ-GitHub), מפעילים מחדש: בריפו → Actions → "Documents keepalive" → Enable workflow. או בטרמינל:

  ```bash
  gh workflow enable invoices-keepalive.yml
  ```

## מעבר לסאב-דומיין

האפליקציה עובדת בנתיבים יחסיים בלבד, אז מעבר לכתובת כמו `docs.bfain.studio` לא דורש שינוי קוד:

1. מפרסמים את התיקייה `invoices/` בכתובת החדשה (ריפו או אתר נפרד, למשל GitHub Pages עם CNAME).
2. ב-Supabase → Authentication → URL Configuration: מוסיפים את הכתובת החדשה ל-Redirect URLs, ומעדכנים את Site URL.
3. נכנסים בכתובת החדשה ומבקשים לינק כניסה. ההתחברות בכתובת הישנה לא עוברת לבד: כל כתובת היא דפדפן "חדש" מבחינת הכניסה.

שני דברים מחוץ ל-`invoices/` משתמשים בכתובת: ה-workflow השבועי (קורא רק את `invoices/config.js`, אז לא צריך לשנות) וה-favicon (בתוך `invoices/assets/`, עובר עם התיקייה).

## עבודה מקומית ובדיקות

**שרת מקומי בלי לגעת בייצור:**

```bash
node scripts/invoices-dev-server.mjs
```

שרת שמחקה את Supabase ומריץ את אותו `install.sql` על Postgres מקומי. האפליקציה נפתחת ב-`http://localhost:4180/invoices/`, ולינק הכניסה מודפס בטרמינל במקום להישלח במייל. אפשר להנפיק כאן מסמכי בדיקה כמה שרוצים: כלום לא מגיע ל-`bfain-docs`, והנתונים נעלמים כשסוגרים את השרת. למעלה מופיע התג "שרת מקומי · נתוני בדיקה בלבד".

**האפליקציה האמיתית מקומית** (מול `bfain-docs`, למשל לפני פרסום):

```bash
node scripts/serve.mjs
```

ואז `http://localhost:4173/invoices/`. זו כבר הייצור: לא מנפיקים כאן לבדיקה.

## אבטחה

- **הריפו ציבורי.** אין בו נתוני לקוחות, מסמכים, הכתובת האישית או מפתחות סודיים. הכל ב-Supabase.
- **`config.js` ציבורי בכוונה:** רק כתובת הפרויקט והמפתח הציבורי (publishable). Supabase בנוי כך שהמפתח הזה גלוי. מי שיש לו רק אותו לא קורא ולא כותב כלום (נבדק).

- **רק בעל החשבון:** כל טבלה מוגנת ב-Row Level Security שמאפשר גישה רק לכתובת fainshteinbar@gmail.com אחרי כניסה. הרשמה חדשה כבויה.
- **מסמך שהונפק נעול בשתי שכבות:** הרשאות שמונעות עריכה ומחיקה מהאפליקציה, וטריגרים במסד הנתונים שמונעים את אותו דבר גם מה-SQL Editor. יומן הפעולות לא ניתן לעריכה או למחיקה.
- **פרטי הלקוח הראשון** נמצאים רק ב-Supabase ובשיחה שבה הוגדרו, לא ב-PLAN.md ולא בבדיקות.
