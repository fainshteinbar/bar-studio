# bfain.studio · מסמכים

אפליקציה להנפקת Invoice, קבלה, הודעת זיכוי והצעת מחיר. הנתונים נשמרים ב-Supabase בלבד, ושום נתון של לקוח או מסמך לא נכנס לריפו. התוכנית המלאה וההחלטות נמצאות ב-[PLAN.md](PLAN.md).

> README מלא (הקמת Supabase צעד אחר צעד, פריסה, גיבוי, מעבר לסאב-דומיין) ייכתב בשלב 6.

## כניסה

הכניסה היא בלינק שנשלח למייל (magic link), רק לכתובת fainshteinbar@gmail.com.

1. במסך הכניסה לוחצים "שליחת לינק כניסה".
2. מגיע מייל מ-Supabase עם לינק. **פותחים אותו באותו דפדפן ובאותו מכשיר שבו ביקשת אותו.** הלינק מאובטח בשיטת PKCE: חלק מהמפתח נשמר בדפדפן שביקש את הלינק, ולכן דפדפן אחר לא יכול להשלים את הכניסה.
3. אחרי הכניסה הדפדפן זוכר אותך, ולינק חדש נדרש רק אם יצאת או ניקית את נתוני הדפדפן.

אם המייל לא מגיע:

- בודקים בתיקיות "קידומי מכירות" ו"ספאם".
- השולח המובנה של Supabase מוגבל לכמה הודעות בשעה. אם ביקשת כמה לינקים ברצף, מחכים כמה דקות.
- לינק תקף לזמן קצר ולשימוש אחד. אם הוא פג, האפליקציה תגיד את זה, ומבקשים לינק חדש.

הגדרה חד-פעמית ב-Supabase (פרויקט `bfain-docs`): Authentication → URL Configuration. Site URL היא `https://fainshteinbar.github.io/bar-studio/invoices/`. ב-Redirect URLs מוסיפים את אותה כתובת ואת `http://localhost:4173/invoices/`. תבנית המייל נשארת הרגילה.

## בעתיד: מעבר לקוד בן 6 ספרות עם Gmail SMTP

ב-Supabase החינמי אפשר לערוך את תבנית המייל רק עם שרת שליחה (SMTP) משלך. Gmail מספיק לזה:

1. **סיסמת אפליקציה ב-Google:** ב-myaccount.google.com מפעילים אימות דו-שלבי, ואז יוצרים App Password (16 תווים). זו סיסמה סודית: מדביקים אותה רק ב-Supabase, לא בצ'אט ולא בריפו.
2. **Supabase:** Authentication → Emails → SMTP Settings → Enable custom SMTP.
   - Host: `smtp.gmail.com`, Port: `465`
   - Username: `fainshteinbar@gmail.com`, Password: סיסמת האפליקציה
   - Sender email: `fainshteinbar@gmail.com`, Sender name: `bfain.studio`
3. **התבנית:** Authentication → Emails → Magic Link. בגוף ההודעה מחליפים את `{{ .ConfirmationURL }}` ב-`{{ .Token }}`, שהוא הקוד בן 6 הספרות.
4. **האפליקציה:** שינוי קטן ב-`js/auth.js` וב-`js/app.js`. במקום להמתין ללינק, מסך הכניסה מציג שדה לקוד, ובודק אותו עם `verifyOtp({ email, token, type: 'email' })`.

היתרון של קוד: אפשר לבקש בטלפון ולהקליד במחשב, או להפך. עם לינק חייבים את אותו דפדפן.

## בדיקות

```bash
npm run test:invoices
```

בדיקות מסד הנתונים (מספור, נעילה, יתרה, הרשאות), על Postgres מקומי בלי שרת.

```bash
node scripts/invoices-auth-check.mjs
```

בדיקת הכניסה בדפדפן מול שרת Supabase מדומה: שליחת לינק, חזרה עם קוד, לינק שפג, לינק מדפדפן אחר, ולחיצה כפולה.

```bash
node scripts/invoices-e2e.mjs
```

בדיקה מלאה של האפליקציה ב-Chrome: לקוח, פרויקט 50/50, חשבון, הנפקה (לחיצה כפולה שולחת בקשה אחת), קבלה בלחיצה, זיכוי, הצעת מחיר שהופכת לחשבון, חסימת תאריך מוקדם, גיבוי, CSV והדפסה. צילומי מסך בטלפון ובמחשב, בהיר וכהה, נשמרים ב-`shots-local/invoices/`.

## עבודה מקומית בלי לגעת בייצור

```bash
node scripts/invoices-dev-server.mjs
```

שרת מקומי שמחקה את Supabase ומריץ את אותו `install.sql` על Postgres מקומי. האפליקציה נפתחת ב-`http://localhost:4180/invoices/`, ולינק הכניסה מודפס בטרמינל במקום להישלח במייל. אפשר להנפיק כאן מסמכים לבדיקה כמה שרוצים: כלום לא מגיע ל-`bfain-docs`, והנתונים נעלמים כשסוגרים את השרת. **בייצור לא מנפיקים מסמכי בדיקה**, כי מספר שהונפק נשאר לתמיד.
